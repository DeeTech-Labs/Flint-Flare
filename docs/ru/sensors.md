# Датчики и системные настройки

Flare получает данные датчиков через общий Core IgniteSDK. При открытии Diagnostics загружается только каталог метаданных: измерения не запускаются. Выберите источник и нажмите **Запустить диагностику**, чтобы создать диагностический доступ на 30 секунд, принадлежащий текущей сессии. Flare продлевает его, пока панель видима и соединение активно. Частота чтения ограничена интервалом источника и максимумом 5 Гц. Уход с панели, скрытие/сворачивание окна и disconnect останавливают диагностику; reconnect её не возобновляет. Если команда остановки потеряется, доступ ограничен сроком действия на устройстве.

Состояние каталога — снимок кэша. Значения отображаются только для актуальных отсчётов. Ожидание, инициализация, отсутствие, устаревание и ошибка не подменяются числовыми заглушками. Виртуальные источники явно помечены. Локальный simulator предоставляет окружающую среду, освещённость, IMU и температуру чипа; последняя не является температурой окружающей среды. Значения, доступность, состояние, сброс и перевод времени вперёд задаются явно и проходят через тот же Core. Перевод времени может завершить диагностический доступ. Lua подключённых часов не запускается повторно на ПК.

Настройки экрана и звука показывают подтверждённый ответ `settings_get`. Поддержка подсветки и mute определяется отдельными флагами устройства: наличие ALS само по себе не означает поддержку подсветки. Автоматическая яркость дополнительно требует ALS. Ручная и резервная яркость допускают 5–100%. После успешного изменения Flare перечитывает настройки и только затем сообщает о подтверждении. Если аппаратная операция завершилась ошибкой после сохранения политики, исходная ошибка остаётся видимой, а Flare перечитывает сохранённую политику; ошибка перечитывания отображается вместе с ней. Simulator хранит виртуальные выходные состояния подсветки/mute через callbacks Core; панель явно помечает их как симуляцию. Физические звук и яркость ПК не изменяются.

Синхронизация времени после принятия и сохранения времени Core опрашивает `time_status` не более пяти секунд. Ошибка RTC отображается отдельно от принятого времени Core. Устройство без RTC подтверждает только время Core. Это не проверка физических RTC или сохранности при отключении питания.

## Сборка и проверки

Интеграция использует SDK `ContractRevision=0x20261115`, commit `8d53e1b`, закреплённый в `platform/`. Обычная сборка использует submodule; FLINT_PLATFORM_DIR остаётся явным override для разработки.

```powershell
cmake -S . -B build/sensors
cmake --build build/sensors --config Debug
ctest --test-dir build/sensors --output-on-failure -C Debug
```

Используйте обычное окружение Qt/compiler для своей платформы. `sensor_sessions` проверяет каталог simulator без автоматического измерения, запуск/остановку/истечение доступа/disconnect, виртуальные состояния и значения, подтверждение времени и ошибки. Физические датчики, USB/BLE, RTC, подсветка/звук, прерывание питания и визуальная компоновка требуют отдельных аппаратных и ручных проверок. Гарантии RAM, задержек, энергопотребления и точности не заявляются.

## SDK revision

SDK датчиков закреплён commit `8d53e1b` в `platform/`. Обычная сборка использует этот submodule; внешний `FLINT_PLATFORM_DIR` нужен только при намеренной разработке нового SDK.
